# Як додати нову лабораторну роботу

Орієнтовно: 1–2 дні для людини, знайомої з React/TypeScript. Робочий приклад —
`src/labs/_template/` (закон Ома): він повністю працює, тож найпростіше — скопіювати його.

## 1. Скопіюйте шаблон

```bash
cp -r src/labs/_template src/labs/06-zener
```

Назва теки: `NN-назва-латиницею`. Номер на початку потрібен, щоб тека потрапила в колекцію
(теки без цифри на початку ігноруються).

## 2. Frontmatter у `index.mdx`

```yaml
number: 6                     # порядок на головній
slug: zener                   # адреса: /labs/zener/  (латиниця, дефіси)
title: Дослідження стабілітрона
shortTitle: Стабілітрон
goal: …                       # мета роботи (1–2 речення) — виводиться автоматично
summary: …                    # опис для картки на головній
equipment:                    # обладнання — виводиться автоматично
  - …
durationMin: 90
draft: false                  # true — сторінку не буде опубліковано
```

Схема полів — `src/content.config.ts`. У `reference.mdx` поставте такий самий `slug`.

## 3. Фізична модель — `model.ts`

- Лише **чисті функції**: без React, DOM і випадковості.
- Одиниці **SI**, одиниця в імені змінної: `voltage_V`, `current_A`, `temperature_K`.
- Типи `Params` (що змінює студент), `Sample` (прихована «істина»), `Truth` (істинні значення).
- `SAMPLES` — навчальні зразки + `X` (зразок кінцевого завдання).
- `referenceAnswers(sample)` — еталонні відповіді **за тією самою процедурою, що й студент**
  (той самий діапазон точок, та сама формула) на даних без шуму.
- Експортуйте `model: LabModel<Params, Sample, Truth>` (`src/core/lab.ts`).
- Використовуйте спільне: `src/physics/materials.ts` (дані матеріалів), `src/physics/sample.ts`
  (σ, R_H, концентрації), `src/core/solve.ts` (`bisect` для нелінійних кіл).

## 4. Тести — `model.test.ts`, `Simulation.test.ts`

- Перевірте кілька відомих значень (напр. «Si-діод: ≈ 0,68 В при 10 мА»).
- **Зворотний тест**: `simulate` → `readInstrument(…, makeRng('t', k))` → обробка формулою
  студента → результат у межах допуску `referenceAnswers`.
- SSR-тест стенда — скопіюйте з шаблону.

## 5. Стенд — `Simulation.tsx`

Складається з UI-кіту `@/components/sim` і схемних символів `@/components/schematic/Schematic`:

```tsx
<Sim>
  <Bench>
    <Panel area="schematic" title="Схема">…</Panel>
    <Panel area="instruments" title="Прилади" dark><Instruments>…</Instruments></Panel>
    <Panel area="controls" title="Керування"><Controls>…<RecordButton/></Controls></Panel>
  </Bench>
  <Workbook>
    <Panel title="Таблиця"><MeasurementTable/></Panel>
    <Panel title="Графік"><Plot/></Panel>
  </Workbook>
</Sim>
```

Обов'язкові правила:

1. Прилади беріть з `src/core/instrumentCatalog.ts` (або додайте новий туди ж).
2. Покази — лише через `readInstrument(spec, range, value_SI, noise.rngFor(ключ, тег))`.
3. Після запису виміру викликайте `noise.next()`.
4. У таблицю пишіть `readingIn(reading, factor)` — число в одиницях стовпця.
5. Ключ таблиці: `useMeasurements('<slug>:<щось>')`. Змінили структуру рядка — змініть ключ.
6. Кнопка запису неактивна з поясненням, якщо прилад зашкалює або коло розірване.
7. Жодних `Math.random()` / `Date.now()` у рендері.
8. Схема: viewBox ≈ 420–520 px завширшки; перевірте на ширині телефону (390 px).

Бракує символу схеми чи елемента керування — додайте в спільний кіт (і задокументуйте в
JSDoc), щоб ним могли користуватися інші лаби.

## 6. Тексти — `index.mdx`, `reference.mdx`

Порядок розділів (`##`): Теоретичні відомості → Віртуальний стенд → Хід роботи →
Обробка результатів → Кінцеве завдання → Контрольні запитання. «Мета» й «Обладнання»
виводяться з frontmatter. Як писати й оформлювати — [CONTENT_GUIDE.md](CONTENT_GUIDE.md).

## 7. Дрібниці

- Піктограма лаби на головній: додайте варіант для свого номера в
  `src/components/layout/LabGlyph.astro` (інакше буде загальний символ).
- Новий матеріал — у `src/physics/materials.ts` (з'явиться і в таблицях довідників).
- Опишіть модель у `README.md` теки лаби: формули, параметри зразків, еталонні відповіді,
  «Ідеї для індивідуальних варіантів» (діапазони параметрів і допуски).

## 8. Перевірка

```bash
npm run test     # тести
npm run check    # типи
npm run build    # збирання без помилок
npm run dev      # пройдіть роботу вручну: виміри, межі приладів, перевантаження, графік, МНК
```
