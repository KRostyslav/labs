# Як редагувати тексти лабораторних (для викладача)

Тексти лежать у файлах **MDX** — це звичайний Markdown (як у вікі чи GitHub) плюс кілька
готових «блоків» (визначення, формула, завдання…). Програмувати не потрібно.

| Що редагуємо | Файл |
|---|---|
| Текст роботи №N | `src/labs/0N-…/index.mdx` |
| Довідник до роботи №N | `src/labs/0N-…/reference.mdx` |
| Загальний довідник | `src/reference/general.mdx` |
| Числа в таблицях матеріалів | `src/physics/materials.ts` (їх же використовують симуляції!) |

## Як побачити результат

- **Локально:** `npm run dev` → http://localhost:4321 — сторінка оновлюється при збереженні.
- **Через GitHub:** відкрийте файл на github.com → ✏️ (Edit) → внесіть зміни → «Commit changes».
  Vercel за хвилину-дві сам оновить сайт. Для великих змін краще створити окрему гілку й
  pull request — Vercel дасть адресу для попереднього перегляду.

## Рецензування у Word

Якщо зручніше працювати у Word: розробник виконує `npm run export:word`, і для кожної лаби
з'являється файл `exports/word/ЛР-N. ….docx` з повним текстом сторінки.

1. Викладач відкриває документ, вмикає **Рецензування → Відстеження змін** і вносить правки
   (або залишає примітки на полях).
2. Розробник переносить прийняті зміни у `src/labs/0N-…/index.mdx` (шлях указано в рамці
   «Примітка для викладача» на початку документа) і перевіряє `npm run build`.
3. Після змін на сайті документи можна перегенерувати тією самою командою.

Скриншот стенда в документі — лише ілюстрація: зміни в роботі стенда (прилади, параметри)
описуйте словами в примітці.

## Основи Markdown

```md
## Розділ (потрапить у бічний зміст)
### Підрозділ

Звичайний абзац. **Жирний**, *курсив*.

1. Нумерований
2. список

- маркований список

| Величина | Одиниця |
|---|---|
| Струм | А |

[Посилання](/dovidnyk/)
```

Порожній рядок між абзацами обов'язковий.

## Формули (KaTeX)

- У рядку: `$I = U/R$`
- Окремим блоком (з порожніми рядками навколо):

```md
$$
\rho = \frac{U\, b\, d}{I\, l}
$$
```

Шпаргалка:

| Потрібно | Пишемо |
|---|---|
| дріб | `\frac{a}{b}` |
| індекс, степінь | `U_{\text{пр}}`, `10^{-19}` |
| корінь | `\sqrt{x}` |
| грецькі | `\alpha \beta \gamma \Delta \varepsilon \lambda \mu \rho \sigma` |
| множення | `a \cdot b` |
| десяткова кома | `1{,}6` (саме так, у фігурних дужках) |
| текст у формулі | `\text{ст}` |
| ln, lg, exp | `\ln R`, `\lg E`, `e^{x}` або `\exp(x)` |

## Готові блоки

Їх можна вставляти в будь-який MDX-файл без жодних import.

```mdx
<Definition term="p–n-перехід">Межа між областями p- і n-типу…</Definition>

<KeyIdea>Опір напівпровідника з нагріванням зменшується.</KeyIdea>

<Note title="Чому так?">Пояснення…</Note>

<Warning>Не перевищуйте струм 50 мА — діод згорить.</Warning>

<Formula name="Закон Ома">

$$
I = \frac{U}{R}
$$

де $I$ — сила струму, А; $U$ — напруга, В.

</Formula>

<FinalTask title="Визначте ширину забороненої зони зразка «X»">

1. …
2. …

</FinalTask>

<ControlQuestions>
  <Question q="Чому ВАХ діода нелінійна?">Підказка, прихована під «Підказка» (необов'язково).</Question>
  <Question q="Що таке пробій?" />
</ControlQuestions>
{/* Підказки вимикаються глобально: SHOW_QUESTION_HINTS у src/site.config.ts (зараз false) */}

<MaterialsTable ids={['Si', 'Ge']} cols={['Eg', 'ni', 'mun', 'mup']} />
<InstrumentsTable ids={['ANALOG_MILLIAMMETER', 'DMM_DCV']} lengthTools />
<ConstantsTable keys={['e', 'k', 'kEv']} />
```

Стовпці `MaterialsTable`: `Eg, ni, mun, mup, rho, cutoff, eps, usage`.
Ключі `ConstantsTable`: `e, k, kEv, h, c, hc, UT, eV, T0`.

## Типові пастки MDX

1. Навколо `$$…$$` і всередині блоків (`<Formula>`, `<FinalTask>`) — **порожні рядки**.
2. Символ `<` у звичайному тексті пишіть як `&lt;` (інакше MDX сприйме його як тег);
   фігурні дужки `{ }` поза формулами — як `\{ \}`. У формулах `$…$` — можна все.
3. Коментарі — лише так: `{/* коментар */}` (HTML-коментарі `<!-- -->` не працюють).
4. Не видаляйте рядок `import Simulation from './Simulation.tsx';` і `<Simulation client:visible />`.
5. Лапки — українські «ялинки»; апостроф — `'`.

Якщо після правки сторінка не збирається — `npm run build` покаже файл і рядок з помилкою.
