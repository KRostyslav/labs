# Віртуальна лабораторія «Фізика напівпровідників»

Статичний навчальний сайт з інтерактивними лабораторними роботами для студентів технічних
коледжів (після 9–10 класу). Кожна робота — окрема сторінка з теорією, віртуальним стендом
(стрілкові й цифрові прилади, ручний запис вимірів, графіки на «міліметрівці»), ходом роботи,
обробкою результатів, кінцевим завданням, контрольними запитаннями та власним **Довідником**.

| № | Робота | Тека | Стан |
|---|---|---|---|
| 1 | Дослідження вольт-амперної характеристики напівпровідникових діодів (Si і Ge) | [src/labs/01-diode-iv](src/labs/01-diode-iv/) | ✅ опублікована |
| 2 | Визначення питомої електропровідності напівпровідників | [src/labs/02-conductivity](src/labs/02-conductivity/) | ✅ опублікована |
| 3 | Температурна залежність електропровідності та ширина забороненої зони | [src/labs/03-band-gap](src/labs/03-band-gap/) | 🔒 прихована |
| 4 | Коефіцієнт Холла, концентрація і рухливість носіїв заряду | [src/labs/04-hall-effect](src/labs/04-hall-effect/) | 🔒 прихована |
| 5 | Внутрішній фотоефект і фотоелектричні прилади | [src/labs/05-photoeffect](src/labs/05-photoeffect/) | 🔒 прихована |

> **Поточний стан (жовтень 2026).** Роботи №3, 4, 5 **тимчасово приховані до подальших
> вказівок**: у їхніх `index.mdx` стоїть `draft: true`, тому їх немає ні на головній, ні в
> навігації, а сторінки (`/labs/<slug>/` і `/labs/<slug>/dovidnyk/`) не генеруються — прямий
> URL відкриває 404. Тексти, моделі й тести лишаються в репозиторії; щоб повернути роботу,
> поставте `draft: false`.
>
> **Підказки до контрольних запитань вимкнено** для всіх робіт: `SHOW_QUESTION_HINTS = false`
> у [src/site.config.ts](src/site.config.ts). Підказки не потрапляють у HTML (їх не можна
> побачити навіть у коді сторінки), але лишаються в MDX-файлах — вмикаються одним рядком.

У кожній теці лаби є `README.md` з описом фізичної моделі, параметрами зразків і еталонними
відповідями кінцевого завдання (для викладача).

## Швидкий старт

Потрібен **Node.js ≥ 22.12**.

```bash
npm install        # встановити залежності (один раз)
npm run dev        # сайт для розробки: http://localhost:4321 (оновлюється при збереженні файлів)
```

| Команда | Що робить |
|---|---|
| `npm run dev` | локальний сервер розробки |
| `npm run build` | зібрати статичний сайт у теку `dist/` |
| `npm run preview` | переглянути зібраний `dist/` |
| `npm run test` | юніт-тести фізичних моделей і ядра (Vitest) |
| `npm run check` | перевірка типів TypeScript / Astro |
| `npm run format` | форматування коду (Prettier; MDX-тексти не чіпає) |
| `npm run export:word` | зібрати сайт і експортувати тексти всіх лаб у Word (`exports/word/`) |

Перед кожним комітом бажано: `npm run test && npm run check && npm run build`.

## Експорт текстів у Word (для рецензування викладачем)

```bash
npm run export:word                                          # усі лаби
python3 scripts/export-word/export_word.py --only diode-iv   # одна лаба (сайт уже зібрано)
```

У `exports/word/` з'являється по одному `.docx` на кожну опубліковану лабораторну (приховані
`draft: true` не експортуються; підказок до контрольних запитань у документі теж немає): увесь текст сторінки
(мета, обладнання, теорія, хід роботи, обробка результатів, кінцеве завдання, контрольні
запитання). Формули — редаговані формули Word, віртуальний стенд — скриншот, блоки
(визначення, «Увага», завдання) — окремі стилі Word. Формат A4, Times New Roman, мова — українська.

Документ Word **не імпортується назад автоматично**: правки викладача (бажано в режимі
рецензування) переносять вручну у `src/labs/NN-…/index.mdx` — див. [docs/CONTENT_GUIDE.md](docs/CONTENT_GUIDE.md).

Потрібно: Python 3 з пакетом `playwright`, Google Chrome (або шлях у змінній `CHROME_PATH`),
pandoc ≥ 3. Скрипт — [scripts/export-word/export_word.py](scripts/export-word/export_word.py).

## Технології

- [Astro 7](https://docs.astro.build) — статичний сайт; сторінки генеруються під час збирання.
- React 19 — лише для інтерактивних стендів («острови», `client:visible`).
- MDX — тексти лаб і довідників (Markdown + компоненти), формули KaTeX (`$…$`, `$$…$$`).
- TypeScript (strict), Vitest, Prettier. Жодних бекендів і баз даних.
- Шрифти Unbounded / Onest / JetBrains Mono (з кирилицею) підключені локально через `@fontsource`.

Залежності оновлено 28.10.2026 до актуальних версій. Свідомо не оновлено: `typescript` 7
(`@astrojs/check` поки підтримує лише TS 5–6) і `@types/node` 26 (проєкт працює на Node 22).
`overrides.katex` у `package.json` змушує `rehype-katex` використовувати ту саму версію KaTeX,
що й CSS сайту (і закриває вразливість старих версій KaTeX).

## Деплой на Vercel

Сайт повністю статичний, окремий `vercel.json` не потрібен.

1. Завантажте репозиторій на GitHub (GitLab / Bitbucket теж підходять).
2. На [vercel.com](https://vercel.com) → **Add New… → Project** → імпортуйте репозиторій.
3. Vercel сам визначить **Framework Preset: Astro** (Build Command `npm run build`,
   Output Directory `dist`). Натисніть **Deploy**.
4. Далі кожен `git push` у гілку `main` автоматично оновлює сайт, а кожен pull request отримує
   власну адресу попереднього перегляду.

Альтернатива без GitHub: `npx vercel` (перший раз) і `npx vercel --prod` з теки проєкту.

## Дані студентів

Сайт нічого не надсилає на сервер. Записані виміри зберігаються лише в `localStorage` браузера
студента (ключі `vlab:<slug>:…`); кнопка «Копіювати» у таблиці переносить дані в Excel /
Google Таблиці. Очищення даних браузера видаляє записи.

## Roadmap

### 1. Індивідуальні варіанти з автоматичною перевіркою (головна ідея на майбутнє)

**Зараз:** кінцеве завдання кожної лаби однакове для всіх — «Зразок X» з фіксованими
параметрами (`SAMPLES.X` у `model.ts`). Відповіді можна «списати в сусіда».

**Ідея:** кожен студент отримує власний «невідомий» зразок і перевіряє свою відповідь на сайті.

#### Як це виглядатиме для студента

1. На початку кінцевого завдання студент вводить ПІБ і групу (або номер варіанту від викладача).
2. Сайт показує **код варіанту** (напр. `K7F2-9QD`) і підставляє у стенд зразок «X» з унікальними
   параметрами (інша концентрація, інший діод, інший матеріал детектора…).
3. Після вимірювань і розрахунків студент вводить відповіді у форму («Eg = … еВ», «тип
   провідності: n / p» …) і натискає «Перевірити».
4. Сайт показує ✓ / ✗ для кожної величини (з допуском, напр. ±5 %), але не показує правильних
   значень. Код варіанту студент записує у звіт.

#### Як це виглядатиме для викладача

- Сторінка `/vykladach/` (не в меню): поле «код варіанту» → еталонні відповіді цього варіанту
  й параметри зразка. Або таблиця для всієї групи за списком ПІБ.
- Будь-який варіант відтворюється за кодом — так само і покази приладів (шум теж детермінований).

#### Технічний план (вже закладено в архітектурі)

| Що | Де | Статус |
|---|---|---|
| Детермінований PRNG (`hashString`, `mulberry32`, `makeRng`) | `src/core/rng.ts` | ✅ є |
| Контракт моделі з `referenceAnswers()` і необов'язковим `generateVariant(rng)` | `src/core/lab.ts` | ✅ є (generateVariant не реалізовано) |
| Перевірка відповідей з допусками `checkAnswers()` | `src/core/lab.ts` | ✅ є |
| Розбір чисел, введених студентом (`1,5·10^-3`) `parseNumberUk()` | `src/core/format.ts` | ✅ є |
| Тести допусків («зворотні» тести в кожній лабі) | `src/labs/*/model.test.ts` | ✅ є |
| Діапазони параметрів для кожної лаби | розділ «Ідеї для індивідуальних варіантів» у `src/labs/*/README.md` | ✅ описано |
| `generateVariant(r)` у кожній `model.ts` | `src/labs/*/model.ts` | ⏳ зробити |
| Компонент «Мій варіант» (ПІБ → код, збереження в localStorage) | `src/components/sim/Variant*.tsx` | ⏳ зробити |
| Форма відповідей + перевірка | `src/components/sim/AnswerForm.tsx` | ⏳ зробити |
| Сторінка викладача | `src/pages/vykladach.astro` | ⏳ зробити |

Кроки реалізації:

1. `code = base32(hashString(labId + ':' + ПІБ_нормалізоване + ':' + група))` — 8 символів.
2. Зразок варіанту: `model.generateVariant(makeRng('variant', labId, code))` — повертає `Sample`
   із діапазонів, описаних у README лаби. Для кожної лаби додати тест: для 1000 випадкових кодів
   `referenceAnswers(generateVariant(...))` проходить `checkAnswers` на даних без шуму.
3. У `Simulation.tsx` зразок «X» береться з варіанту, а не з `SAMPLES.X`; шум — з
   `makeRng('noise', code, номер_виміру)` (у `useNoise` додати код варіанту до ключа).
4. `AnswerForm` рендерить поля за `referenceAnswers()` (label, unit, kind) і показує ✓/✗ через
   `checkAnswers()`. Кількість спроб можна обмежити (лічильник у localStorage).
5. Сторінка викладача рахує ті самі функції для введеного коду.

**Обмеження:** сайт статичний, тож еталонні відповіді обчислюються в браузері — технічно
підготовлений студент може їх дістати з коду. Для коледжу це прийнятно. Для суворого контролю —
перенести `generateVariant`/`checkAnswers` у серверну функцію (Vercel Functions) з секретною
«сіллю» в змінній оточення; інтерфейс лаб при цьому не зміниться.
